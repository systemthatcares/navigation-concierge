# Profiling Agent v0.1 — Spec Note for Shota

*From Matthew (drafted by Friday), 2026-08-03.*
*Amends the consult spec in `2026-05-14_navigation_concierge_block1_memo.md`. Reference implementation shipped same day in `2026-07-19_hackathon/profiling_agent_v0/`.*

## What testing surfaced

Two findings from working the v0 prototype, one about the exit logic, one about an input.

**The spouse short-circuit is not safe.** v0 fires an early "high-confidence recommendation" when the spouse SEP is open and nobody is mid-treatment. But one skipped question, income under $40k, swings the scorecard 3 points (ACA +2, spouse takes -1 for forfeiting the subsidy) and flips the winner. Same person, different recommendation, depending on which button they clicked. The confidence claim was not true.

**"Active care" as a yes/no question collapses a huge stakes range into one bit.** A patient who gets an occasional Viagra refill and a patient on every-3-month cystoscopy surveillance for bladder cancer can both truthfully answer yes. v0 prices both at the same +2 for COBRA continuity, which means it recommends paying 102% of full premium for continuity that, in the refill case, is worth a phone call. The error is upstream of the scorecard: the input doesn't mean what the model assumes it means.

## Change 1 (input): stratify the care question

Do this first. Change 2 depends on it.

Replace the boolean with a tier, collected in two lay-answerable questions:

1. Gate: "Is anyone who needs coverage getting ongoing medical care right now?" No → tier `none`.
2. Tier: "Which is closest?" The test to keep in mind: if you had to switch doctors mid-course, would it be unsafe, a real setback, or mostly paperwork?
   - "In the middle of treatment: chemo or radiation, staged surgery, pregnancy, or a procedure already scheduled" → `episode`
   - "Regular monitoring with a specialist every few months" → `surveillance`
   - "Stable: ongoing prescriptions and routine checkups" → `chronic`

Scorecard weights per tier (replaces the old single care row):

| Tier | COBRA | ACA | Spouse | Short-term | Bare |
|---|---|---|---|---|---|
| episode | +3 | -2 | -1 | -2 | -2 |
| surveillance | +1 | verify | verify | -1 | -1 |
| chronic | 0 | verify | verify | -1 | 0 |
| none | 0 | 0 | 0 | 0 | 0 |

Notes on the numbers:
- `episode` rises from +2 to +3 (and ACA to -2) deliberately. The old design asserted "care dominates cost" out-of-band, in a hand-written short-circuit that overrode the scorecard. v0.1 moves that clinical judgment into the weight itself, where the exit logic (Change 2) can see it and prove it. Mid-treatment continuity now outranks subsidy arithmetic inside the scorecard, which matches the clinical reality for the tier that actually means mid-treatment.
- `surveillance` gets a moderate nudge plus verify flags ("confirm your specialist is in the new network and your surveillance schedule transfers without delay") instead of penalties, because the specialist may well be in the new network. Uncertainty, not known harm.
- `chronic` carries zero continuity weight. What matters for stable patients is the formulary, and the specialty-Rx question already handles the expensive case. Verify flags cover the rest.

## Change 2 (exit): replace short-circuits with a clinch check

Both hand-written short-circuits are removed (Matthew's ruling). In their place, one rule: **offer an early exit only when the remaining questions mathematically cannot change the recommendation.**

Because the scorecard is deterministic and only three remaining fields affect scores (income band, specialty Rx, new-coverage-soon; the premium question is display-only), the check is exhaustive: enumerate every combination of unanswered values (at most 3 x 2 x 3 = 18), run the full scorecard on each, and see whether the same path wins every time. If yes, the consult is clinched, and the bot may say, truthfully: "the remaining questions can't change this answer, only refine the fine print."

The election-night analogy: you call the race when the uncounted ballots can't change the outcome, not when a pundit feels good about it.

Behavior that falls out with the new weights, no special-casing:
- Mid-treatment (`episode`) clinches for COBRA right after the care questions, in every branch of the remaining answers. That user keeps the 4-question fast consult, now with a claim that is provably true.
- The spouse-SEP case never clinches before income is asked, because income genuinely can flip it. That user correctly gets asked about income first. This is the regression test.
- Surveillance clinches only after income comes back subsidy-negative. Certainty rises mid-consult, which is exactly the "when does certainty rise in the algorithm" question, answered by arithmetic.

UI rules: check for a clinch after the care questions and after each scoring question; offer the exit at most once per consult; if declined, finish all questions and never re-offer. All "high-confidence" phrasing is gone.

## Unchanged, still open (from the v0 limitations list)

- Subsidy eligibility is still the income-band heuristic, not real 2026 FPL/benchmark math. Separate work item.
- Spouse SEP window still defaults to 30 days.
- CA-tuned; Medi-Cal/CHIP still absent from the option set, which matters for the family personas. Separate work item, arguably the biggest content gap.
- Care tier is still self-report; the tiers make good-faith answers land in the right bucket, they don't defend against wrong ones.
